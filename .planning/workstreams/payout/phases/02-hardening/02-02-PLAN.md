<objective>
Add failure retry + terminal DEAD + alert-once to the payout slice (RETRY-01), reusing the already-verified status-guarded atomic UPDATE idiom (`applyResult`) and the shipped cancel-restore DEAD-status idiom. A `retryFailed()` pass is added to `PayoutResultService` and invoked from the EXISTING `PayoutPollScheduler` tick (same Redisson lock, no new bean). FAILED payouts under the attempt cap are atomically claimed and re-submitted with the same transfer_ref; exhausted ones go terminal DEAD with exactly one operational alert.

RESOLVED design (per Phase-2 brief / RESEARCH fork A1): terminal state is a new `DEAD` value in the EXISTING `payout.status VARCHAR(20)` (values now PROCESSING|PAID|FAILED|DEAD). This honors spec §4's intent (terminal after max retries + alert once) with NO new Flyway migration — attempt_count/last_error already exist in V2, ddl-auto=validate checks column shape not values, and there is no CHECK constraint. This keeps the Phase-1 INV-01 gate passing verbatim (still V2-only).

Purpose: make failed transfers self-heal up to a cap and surface unrecoverable ones exactly once, without perturbing the Phase-1 convergence chokepoint or adding a scheduler bean.
Output: two new guarded UPDATEs (claim + dead), a `retryFailed()` pass wired into the poll scheduler, `payout.retry.*` config, and an integration test proving resubmit + attempt++, DEAD + exactly-one alert at cap, and no re-alert after DEAD.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| poll scheduler tick → payout rows | overlapping ticks / webhook-vs-poll must not double-resubmit or re-alert |
| payout FAILED exhaustion → OperationAlertPort | an alert storm (re-alerting every 60s) is a self-DoS |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Tampering | double-resubmit from two ticks | high | mitigate | atomic claimForRetry (FAILED→PROCESSING guarded UPDATE); submit only when rowcount==1; Redisson single-runner lock is defense-in-depth |
| T-02-04 | Denial of Service | alert storm re-alerting exhausted rows | medium | mitigate | exactly-once via guarded FAILED→DEAD transition; alert only inside rowcount==1 branch; DEAD rows never re-match the FAILED select (asserted by times(1) across two ticks) |
| T-02-05 | Tampering | DEAD value breaks ddl-auto=validate / adds stray migration | medium | mitigate | DEAD is a new value in existing status VARCHAR(20); no CHECK, no DB enum → no migration; INV gate (02-03) asserts still V2-only |
