<objective>
Deliver the payout end-to-end happy path as a tracer through every layer of settlement-service: set a merchant payout account, approve a FINALIZED settlement into a PROCESSING payout submitted to a mock bank, and converge PROCESSING→PAID via a signature-verified webhook — with the poll backstop wired to the same convergence chokepoint. payment/order/product/merchant are untouched (net is read from settlement's own row).

Purpose: prove the payout architecture — Flyway V2 tables, the two entities, the BankTransferPort mock, the status-guarded applyResult UPDATE, the webhook signature path, and the Redisson poll scheduler — works wired together on one real path before Plan 02 rounds out queries/validation and Plan 03 gates INV-01.

Output: 2 new tables (V2), Payout + MerchantPayoutAccount (domain + JPA + repo + Impl + @Bean wiring), BankTransferPort + mock + HTTP stub, PayoutService/PayoutResultService, PayoutPollScheduler, three controllers + DTOs, application.yml keys, and three ITs (tracer e2e, poll backstop, mock unit).

## Resolved open questions (encoded in this plan)
- **transfer_ref = "PO-" + settlementId** (NOT payout.id). The id is AUTO_INCREMENT and unknown until INSERT, but transfer_ref is NOT NULL — deriving it from settlementId makes it known at approval, keeps it deterministic, and uk_payout_settlement(settlement_id) already guarantees one payout per settlement, so it is unique. This deviates from the literal spec §3 text ("transfer_ref = String(payout.id)"): a single JPA save, no second UPDATE.
- **Webhook secret transport = X-Bank-Signature HEADER**, compared constant-time via java.security.MessageDigest.isEqual against ${payout.webhook.secret}. Checked in-controller (settlement-service has NO Spring Security — verified), no Servlet Filter. Mismatch returns 401 and leaves state unchanged.
- **Errors follow the existing settlement convention**: validation failures throw IllegalArgumentException (mapped to 400 by GlobalExceptionHandler.java:24-28). No shared ErrorCode enum edit. The webhook 401 is returned as a ResponseEntity status directly (a thrown exception would be swallowed to 500 by the handler's Exception catch-all — GlobalExceptionHandler.java:30-35 has no 401/404 mapping).
</objective>
