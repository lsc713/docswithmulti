## 요약

결제를 상류 주문에 신뢰 가능하게 연결. 결제 생성 시 orderItemId를 order-service에 존재·소유 검증(order.user_id == X-User-Id)하고 `payment.order_id` 강한 링크(NOT NULL, V18)를 건다. 취소 코어 불변(CANCEL-01), 주문→결제 디커플링 유지.

## 주요 성과 (accomplishments)

1. order-service `POST /v1/orders/items:verify` — 존재 + 단일 order + 소유 검증, `OrderItemVerifier` 도메인 POJO, 200/404/409/403.
2. 신뢰 신원 전환 — 주문·결제 생성 모두 body `userId` 제거, `X-User-Id` 신뢰헤더 사용.
3. 게이트웨이 `POST /v1/orders` secured 라우트(정확 경로 매칭 — 내부 `items:verify` 미노출) + order NetworkPolicy.
4. payment `OrderVerifyHttpClient` fail-closed(ProductStock 미러) + `CreatePaymentService` verify-first(재고 예약 전) + `payment.order_id` NOT NULL(Flyway V18).
5. 취소 코어 불변 — CANCEL-01 게이트(Cancel*/스케줄러/outbox diff 0), 7-arg `Payment.of` 유지+8-arg 신규(orderId=0 sentinel)로 취소 픽스처 무편집, 취소 IT 그린.
