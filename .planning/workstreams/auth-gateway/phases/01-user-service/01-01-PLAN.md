<objective>
user-service 신규 모듈을 참조 브랜치 `origin/feat/user-product-resilience`에서 **이식(port)**하여,
회원가입→저장→로그인→access+refresh 발급이 Testcontainers 통합테스트로 그린이 되는
최소 end-to-end 프로덕션 슬라이스를 만든다. 이 tracer가 AUTH-01/AUTH-02를 e2e로 증명하고,
동시에 AUTH-03(refresh)·AUTH-04(logout) 코드도 같은 `AuthService`/`AuthController`에 함께 착지한다
(그 검증은 Plan 02 확장 task).

Purpose: 인증 경계의 신원·토큰 발급을 헥사고날 규약 그대로 확립하고, Boot 4.0.5/Security 7 무수정
컴파일(MEDIUM 신뢰도, build-note)을 빌드로 확정한다.
Output: 컴파일·기동·테스트 그린인 user-service 모듈 + signup→login 통합테스트.

이식이지 발명이 아니다. PORT 파일은 `git show <branch>:<path>`로 그대로 복사하고, ADJUST 파일만 손으로 수정한다.
브랜치 merge 절대 금지(main보다 110커밋 뒤 — 취소 코어를 되돌림).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /v1/auth/signup,login | 미인증 공개 입력. 특권 필드(role/merchantId) 자기지정 시도 지점 |
| app → user_db | JPA 파라미터 바인딩(raw SQL 없음) |
| env → JwtTokenProvider | JWT_SECRET 주입(≥256bit) — 서명 키 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | AuthController.signup / SignupRequest | high | mitigate | D-P1-2: SignupRequest에서 role/merchantId 제거 + 컨트롤러가 UserRole.USER 강제. Task 3 통합테스트 3번이 회귀 고정 |
| T-01-02 | Spoofing/Tampering | JwtTokenProvider secret | high | mitigate | D-P1-3: dev 기본값 제거, 비-local 프로파일 JWT_SECRET 미주입 시 fail-fast. Keys.hmacShaKeyFor가 <256bit 거부(Pitfall 5). fail-fast 검증은 Plan 02 |
| T-01-03 | Info Disclosure | 비밀번호 저장 | medium | mitigate | BcryptPasswordEncoderAdapter(cost 10) — 평문 저장 없음. 자체 해시 금지(Don't Hand-Roll) |
| T-01-04 | Tampering | Maven 의존성(jjwt 0.12.6, spring-security) | low | accept | RESEARCH §Package Legitimacy Audit 전부 OK/Approved(Maven Central, 공식). ASSUMED/SUS 없음 → 체크포인트 불요 |
| T-01-05 | Tampering | SQL injection | low | accept | Spring Data JPA 파라미터 바인딩만, raw SQL 없음 |
