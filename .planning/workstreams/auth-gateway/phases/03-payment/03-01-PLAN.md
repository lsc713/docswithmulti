Spring/JPA/lombok 어노테이션·repository·carrier 타입 의존 금지, primitive 만 받는다 (D-P3-4). 메서드 authorize(String role, Long headerMerchantId, Long targetMerchantId) : role 이 "ADMIN" 이면 즉시 반환(전체 허용); role 이 "MERCHANT" 이고 headerMerchantId 와 targetMerchantId 가 모두 non-null 이며 값이 같으면 반환(본인 가맹점 허용); 그 외(USER·role 누락·불일치·merchantId 누락)는 CancelNotAuthorizedException 을 던진다. 정책은 D-P3-2. role 비교는 String equality, merchantId 비교는 Long.equals 값 비교. 참조 AuthenticatedUser.validateCancelAuthorization 의 USER self-cancel 분기는 채택하지 않는다(우리 정책 USER→403).

    application/authz/AuthenticatedUser 를 얇은 carrier record 로 신규 작성한다 (String userId, String role, String merchantId). 신뢰 헤더 원문을 담기만 하는 순수 record — 판정 로직/보안 어노테이션 금지 (참조 자산 ADAPT: USER self-cancel 판정 제거, D-P3-3). userId 는 인가에 사용하지 않고 감사 로깅 용도로만 보관한다 (D-P3-7).

USER·role 누락 경로는 로드 없이 targetMerchantId=null. 마지막에 CancelAuthorizer.authorize(role, headerMerchantId, targetMerchantId) 를 호출해 최종 허용/거부를 domain 이 판정하게 한다. 클래스 javadoc 에 신뢰 경계 가정을 남긴다: payment(8080) ingress 는 게이트웨이 파드에서만 허용되어야 하며(k3s NetworkPolicy, 배포 시점 이관), payment 는 헤더 role 을 무검증 신뢰한다 (D-P3-6). spring-security·jjwt 의존 추가 금지, JWT 재검증 금지 (D-P3-3).
