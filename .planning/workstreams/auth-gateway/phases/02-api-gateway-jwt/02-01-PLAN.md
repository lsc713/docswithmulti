<objective>
신규 무상태 모듈 `api-gateway`(포트 8000)를 스캐폴드하고, **한 경로(payment 취소)를 모든 레이어로 관통하는
최소 end-to-end 슬라이스**를 만든다: 유효 JWT → 게이트웨이 라우팅 → JWT 검증 → 신뢰 헤더 주입 →
WireMock downstream이 X-User-Id/X-User-Role 수신 → 통합테스트 그린. 이 tracer가 GATE-01(라우팅)과
GATE-02(신뢰 헤더 전달) happy path를 e2e로 증명하는 동시에, RESEARCH의 유일한 잔여 리스크인
**Spring Cloud BOM ↔ Boot 4.0.5 정합(A1)** 을 `:api-gateway:build`로 확정한다.

Purpose: 게이트웨이 3책임(라우팅/검증/헤더주입)의 아키텍처를 최소 슬라이스로 검증해, 확장 전에
BOM 호환·무상태 기동·필터 API(A3)를 빌드로 못박는다.
Output: 컴파일·기동·통합테스트 그린인 api-gateway 모듈 + payment 경로 신뢰헤더 전달 IT.

신규 구현이다(참조 브랜치에 게이트웨이 없음). RESEARCH.md가 스택/패턴/좌표를 처방했으니 그대로 따르되
코드는 새로 작성한다. Spring Security 도입 금지, 리액티브(webflux) 게이트웨이 금지.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → gateway :8000 | 미인증 외부 입력. Authorization JWT + 위조 시도되는 X-User-* 헤더가 여기서 교차 |
| gateway → downstream | 신뢰 네트워크 내부. downstream은 X-User-* 헤더만 신뢰(재검증 없음) |
| env → JwtVerifier | JWT_SECRET 주입(≥256bit, user-service와 동일 값) — HS256 검증 키 |
