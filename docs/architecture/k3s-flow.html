1. 취소 라운드트립 (동기 경로 + 인라인 발행)

Traefik → payment 파드(3중 1택) → risk → merchant-limit(클러스터 DNS) → 외부 DB. 멱등은 request_hash UK, 재계산은 findAllByPaymentIdForUpdate 행락. TX3 커밋과 payment.cancelled 인라인 발행이 커플링(발행 실패 = 롤백).
주의(홉 배치 가변): payment→risk→merchant-limit 홉은 파드가 같은 agent면 호스트 내 통신(네트워크 없음), 다른 agent면 flannel VXLAN 크로스노드 — anti-affinity를 안 걸어 스케줄러 배치마다 다르다. (load-test는 payment/risk 단독 EC2라 항상 고정 크로스-EC2. 그래서 두 리그 홉 지연은 직접 비교하지 않는다.)

3. 분산 스케줄러 (멀티 파드 = 1개만 실행)

@Scheduled 폴러는 파드마다 뜨므로 Redisson 분산락으로 한 파드만 실행. payment 복구 3종 + merchant-limit outbox 발행. (실측: outbox 5이벤트 → Kafka 정확히 5 = exactly-once.)
