# 상품 상세 재고 표시·캐시 PRD

## 개요

상품 상세 캐시의 효율을 유지하면서 재고 표시와 품절 상태를 관리하고, `reserve`를 재고의 최종 권한으로 유지한다.

## 사용자 스토리

- 구매자는 상품 상세에서 재고 수량과 품절 상태를 확인한다.
- 구매자는 stale 화면을 보고 구매를 시도하더라도 oversell 없이 재고 부족 안내를 받는다.
- 운영자는 혼합 ramp 측정으로 구간별 병목 인스턴스를 확인한다.

## 기술 결정

### 재고 상태 분리 캐시

**Context** — 상품 상세 본문 캐시에 가용 재고를 함께 저장하면 재고 예약·해제마다 상세 캐시 전체를 무효화해야 한다. 반대로 재고를 매번 MySQL에서 조인하면 읽기 부하가 캐시 효과를 상쇄한다.

**Decision** — 상품 본문·가격은 기존 Product detail 캐시에 유지한다. 가용 재고와 품절 상태는 `product:stock:{productId}` Redis 키로 분리한다. `reserve`·`release` 트랜잭션이 성공한 뒤에만 해당 키를 갱신한다. 상세 조회는 재고 상태 키를 먼저 읽고, miss 또는 Redis 오류이면 MySQL `product_stock`에서 읽어 다시 채운다. `reserve`의 조건부 차감은 최종 구매 가능 여부를 계속 판정한다.

**Alternatives**

- 상세 캐시 전체 무효화: 재고 변경마다 이름·이미지·설명까지 다시 조립해야 하므로 hot 상품의 cache churn과 MySQL miss를 키운다.
- 재고 매번 MySQL 조회: 구현은 단순하지만 상세 조회 트래픽이 MySQL 읽기 부하로 직접 전파돼 현재 캐시 전략의 목적을 훼손한다.

**Consequences**

- 장점: 재고 변경이 상품 본문 캐시 hit율에 주는 영향을 줄이고, 품절 상태를 빠르게 갱신할 수 있다.
- 단점: Redis 재고 상태와 MySQL 원본의 일시적 불일치를 관리해야 하며, cache miss·갱신 실패 fallback 경로를 테스트해야 한다.

## Out of Scope

- WebSocket/SSE 기반 실시간 재고 푸시
- 판매자 재고 관리 UI
- 다중 리전 재고 동기화
- 가격 변경 API 신설 및 가격 갱신 정책 변경
- Redis 장애를 위한 별도 복제·클러스터 구성
- 실제 트래픽 비율 자동 추정
